A student cannot begin logging hours until the required clearance process is complete and a Program Admin approves the submission.

Step 10 is the launch gate: review the first submissions carefully because they validate the terms, tracks, sites, agreements, supervisor routing, and insurance requirements configured in the previous steps.

## Find students waiting for approval

Use any of these paths:

1. **Overview → Pending Tasks**
2. **Overview → More filters → Application Status → App: Pending Approval**
3. Open a flagged student row
4. **My Program → Activity Log → Type: Application Forms**

## Review the complete submission

Open the student's **Student Details → Documents** tab. Confirm:

- Correct academic term
- Correct track and level
- Required agreements completed
- Appropriate established or requested site
- Correct supervisor name and email
- Liability insurance or other required uploads
- Track-specific and level-specific requirements
- Custom questions, quizzes, and embedded forms
- Any conditional step was completed only when applicable

<Warning>
  Do not approve a submission simply because every row has a checkmark. Confirm that the data is internally consistent and that the site, supervisor, track, and signer routing match the intended placement.
</Warning>

## Approve or reject

When the submission is pending:

- **Approve** — unlocks Field Experience so the student can log hours and participate in assigned cohorts
- **Reject** — returns the submission to the student with a required correction note

Write a specific rejection note such as “Upload the liability policy showing the expiration date” instead of “Insurance is wrong.”

An approved application can later be changed to **Rejected** if a credential expires or the placement must be corrected.

## Updated applications

A student may update an approved application, for example to add a site or change placement information. The existing approval remains active while the update is pending.

Review the new version like a first submission. Approval replaces the previously approved version without unnecessarily blocking an active student.

## Before approving the first student

Complete this check once for every newly configured program:

- [ ] Terms and tracks are correct
- [ ] Total, direct, indirect, and supervision requirements are correct
- [ ] The student's site and supervisor are correct
- [ ] Every agreement reached the intended signer
- [ ] Required insurance and credentials are visible
- [ ] The cohort uses the correct hours report template
- [ ] Recurring schedules have the intended dates and signers
- [ ] View as Student shows the expected post-approval dashboard
- [ ] Faculty and supervisor access has been tested

Use the [Launch Readiness & QA Checklist](/fieldx/launch-readiness-qa) for the complete program-level review.

## Submission windows and extensions

Programs can restrict new applications using term submission windows and grant individual extensions when needed. Level- and track-specific overrides are also available.

Keep those rules separate from the approval decision itself. See [Designing Clearance & Agreements](/fieldx/designing-clearance-agreements#submission-windows-and-extensions) for configuration and precedence.

## Handling a large approval queue

For large cohorts:

- Filter the Overview table by application status, track, and term
- Review students in consistent batches
- Do not treat a bulk filter as a substitute for reviewing each placement
- Use the Activity Log as the exportable record of decisions

If a student already completed clearance outside FieldX during a migration, a Program Admin can waive that individual's clearance from the member record. After a waiver, manually connect the student to the correct site and supervisor because the normal clearance flow did not create those links.

<Note>
  Approval is complete when the student can reach the Field Experience dashboard, sees the correct cohort and placement, and can begin the intended hour-logging workflow.
</Note>
