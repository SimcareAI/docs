FieldX forms include evaluations, surveys, agreements, clearance documents, and other structured paperwork. Programs usually begin with forms converted from their existing PDF or Word documents, then review them in the form builder before assigning them.

<Warning>
  A form is not ready because it merely looks like the source document. Before launch, verify who completes every question, which signatures are required, and the order in which the form moves between people.
</Warning>

## Start with the source set

Before editing:

1. Reconcile the files uploaded during onboarding with the program's complete form list.
2. Identify anything that was mentioned but not successfully uploaded.
3. Confirm that each source file is readable and is the current version.
4. Name the intended respondents and signers for every form.
5. Mark which forms are required, optional, recurring, or used only for certain tracks or levels.

## Create or import a form

Open **Assignments** and select **Create Assignment → Form**.

You can:

- **Build New** — start with a blank form and add fields manually
- **Upload** — convert an existing PDF or Word document into a FieldX form with AI

After an AI import finishes, treat the result as a draft. Compare it with the source document question by question.

## Available field types

| Type | Use case |
| --- | --- |
| **Text input** | Short responses and numeric entries |
| **Text area** | Paragraph responses |
| **Checkboxes / radio buttons** | Single- or multiple-choice questions |
| **Rating scales** | Likert scales and evaluation matrices |
| **Date & time** | Dates and time-based entries |
| **File upload** | Supporting documents |
| **Signature** | Student, site supervisor, faculty, or custom signers |
| **Section header** | Instructions and visual organization |
| **Accumulate numbers** | Sum, average, minimum, maximum, or count of earlier numeric responses |

## Assign every question to the correct role

Every question must have a person responsible for completing it. Depending on the form, that may be:

- Student
- Site supervisor
- Faculty supervisor
- Program Admin
- A named custom signer

Use client-facing labels, especially for custom signers. Avoid generic names such as “Signer 2” when the real role is “Field Placement Director” or “Provost.”

<Warning>
  When you remove a respondent role, review any questions previously assigned to that role. Reassign or delete orphaned questions before saving.
</Warning>

## Configure signatures and routing

Decide:

- Whether the student signs
- Whether the site supervisor signs
- Whether faculty signs
- Whether a custom person signs
- The order in which signatures are requested
- Whether the signer should be selected automatically or entered by the student

Multi-signer workflows are sequential. A final signer will not receive the form until every earlier signer has completed their step.

If an affiliation agreement must be signed by someone other than the student's site supervisor, ask for that person's email explicitly instead of automatically routing to the supervisor.

## Accumulate numbers

Use **Accumulate numbers** for totals or calculated results based on earlier numeric questions.

1. Add the numeric **Text input** questions first.
2. Add an **Accumulate numbers** field after them.
3. Select the source questions.
4. Choose **Sum**, **Average**, **Min**, **Max**, or **Count**.
5. Set the number of decimal places.

Only numeric questions above the calculated field can be selected. Blank and non-numeric answers are skipped.

## Required form QA

Open every form and check:

- [ ] The title matches the program's language
- [ ] Every source question is present
- [ ] No question was duplicated during import
- [ ] Every question belongs to the correct respondent
- [ ] Student signature is present when required
- [ ] Site supervisor and faculty roles are not reversed
- [ ] Custom signers have accurate labels
- [ ] Required fields are actually required
- [ ] Conditional instructions appear where the user needs them
- [ ] Rating scales preserve their original labels and order
- [ ] The form opens cleanly at normal browser zoom
- [ ] A completed test submission renders correctly as a PDF
- [ ] Multi-signer status shows the expected next signer

## Editing a form after assignment

Saving a form updates the reusable template. Existing assignments keep the version originally presented unless you explicitly choose to update live assignments.

When a new required role is added, FieldX asks whether to:

- **Save template only** — future assignments use the new role; current assignments stay unchanged
- **Save and update existing assignments** — current assignments receive the new role, and completed items may reopen until that person responds

Previously submitted responses are preserved. FieldX versions the question set so older submissions and exports continue to render against the form the respondent originally saw.

<Warning>
  Updating live assignments can turn completed work back into pending work. Notify affected students and signers before choosing that option.
</Warning>

## Before assigning the form

Confirm whether the form should be:

- Assigned once
- Assigned on a recurring schedule
- Assigned to a whole cohort
- Assigned only to selected individuals
- Included in a reusable group
- Added to a template cohort

Then continue to [7. Creating & Assigning Forms & Reports](/fieldx/step-4-create-assign-tasks).
