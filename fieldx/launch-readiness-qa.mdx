Use this checklist after completing Steps 1–9 and before approving the first student.

## Program structure

- [ ] Program name, logo, and description are correct
- [ ] Track and level names match the program's language
- [ ] Unused tracks are disabled
- [ ] Academic terms have correct start and end dates
- [ ] Submission windows and extensions are configured only when needed
- [ ] Re-clearance rules match the program's policy

## Hour requirements

For every track and level:

- [ ] Total required hours are correct
- [ ] Direct hours are correct
- [ ] Indirect hours are correct
- [ ] Supervision hours are correct
- [ ] Activity types count toward the intended categories
- [ ] The cohort uses the correct hours report template
- [ ] The reporting cadence and required signers are confirmed
- [ ] Every recurring schedule has a start date and end date

<Warning>
  Supervision requirements are especially easy to misconfigure. Compare them with the program's approved curriculum or accreditation requirements instead of relying on a default.
</Warning>

## Forms and agreements

Open every launch-critical form:

- [ ] All source questions are present
- [ ] No duplicated or orphaned questions remain
- [ ] Each question belongs to the correct respondent
- [ ] Student signatures are present where required
- [ ] Site supervisor and faculty roles are not reversed
- [ ] Custom signers have accurate labels
- [ ] Sequential signer order is correct
- [ ] Conditional instructions appear in both the step description and form
- [ ] A completed test submission renders correctly as a PDF

## Sites and supervisors

- [ ] Site list was reconciled with the source file
- [ ] Duplicate sites were merged or removed
- [ ] Expired and inactive sites are not presented as active
- [ ] Affiliation-agreement dates are present where available
- [ ] New-site approval behavior is correct
- [ ] One supervisor invitation was tested
- [ ] Supervisor profile requirements are documented
- [ ] The authorized agreement signer is not being replaced by the site supervisor

## Members and access

- [ ] Every Program Admin has the correct role
- [ ] Faculty are in the correct cohorts
- [ ] No students were accidentally added as instructors
- [ ] Credential emails were sent or self-sign-up instructions were provided
- [ ] SSO or domain-based enrollment was tested
- [ ] LMS integration is connected to both the institution and FieldX program
- [ ] LMS cohort links were tested inside the client's course

## Student experience

Using [9. Testing With View as Student](/fieldx/step-0-1-testing-fieldx-with-your-sandbox):

- [ ] Clearance instructions are understandable
- [ ] Correct term, track, site, and supervisor choices appear
- [ ] Assigned work appears on the expected dates
- [ ] Locked and approved states behave correctly
- [ ] Support access is visible

Using populated demo data:

- [ ] Overview KPIs and graphs display
- [ ] A weekly hour report is complete
- [ ] A generated PDF was reviewed
- [ ] Faculty and supervisor queues were checked
- [ ] One standard report was run successfully

## Rollout and support

- [ ] Program Admin credentials were sent
- [ ] Walkthrough recording was sent
- [ ] Faculty orientation is scheduled or intentionally skipped
- [ ] Student orientation is scheduled or intentionally replaced by a recording
- [ ] Supervisor instructions are ready
- [ ] Support page, office hours, and contact route were shared
- [ ] Client knows how to report a bug or request
- [ ] A post-launch check-in is scheduled near the first pressure point

## Ready to approve

The program is ready when the configuration is correct, the first complete workflow has been tested, and the people responsible for launch know what happens next.

Continue to [10. Approving Students](/fieldx/step-3-1-approving-students).
