Hour configuration determines what students can log, how progress is calculated, and who must approve the record. Confirm these decisions with the program before creating report templates or recurring schedules.

## Collect the requirements

For every track and level, collect:

| Decision | Example |
| --- | --- |
| Total hours | 600 |
| Direct hours | 240 |
| Indirect hours | No minimum |
| Supervision hours | 45 |
| Reporting cadence | Weekly |
| Student signature | Required |
| Site supervisor signature | Required |
| Faculty signature | Monthly only |
| Ethics code | ACA, ASCA, AMHCA, AAMFT, NASW, or program-specific |
| Activity types | Individual counseling, group counseling, supervision, documentation |

Use the program's approved numbers and names. Do not assume that two programs in the same discipline use identical requirements.

## Configure tracks and levels

Open **My Program → Terms and Tracks**, then edit each track.

Confirm:

- Total, direct, indirect, and supervision requirements
- Which activity types qualify for each hour category
- Site requirements
- Whether the track is enabled
- Whether certificate requirements also apply

Disable an unused track when it may be needed later. Delete only when the program is certain it should not remain available.

## Activity types

Activity types should be understandable to students and specific enough for reporting.

For each activity type, decide:

- Student-facing label
- Definition or example
- Whether it counts as direct, indirect, supervision, or another category
- Which tracks and levels use it
- Whether the program needs a minimum or only wants to report on it

If the activity type is not self-service in the current environment, send the approved list to the SimCare contact for configuration.

<Warning>
  Avoid creating an indirect-hours minimum simply because an indirect category exists. Some programs track indirect hours without requiring a minimum.
</Warning>

## Supervision requirements

Check supervision separately for every track and level.

Questions to ask:

- Is there a minimum number of supervision hours?
- Is the requirement weekly, cumulative, or both?
- Must supervision be individual, group, or either?
- Does the faculty supervisor sign every report or only certain periods?
- Can supervision requirements accumulate across practicum and internship?

When the platform cannot enforce a nuanced rule, document the rule and use reports to monitor it.

## Signature cadence

The report template defines who signs. The recurring schedule defines when a new report is generated.

Common models:

| Model | Student | Site supervisor | Faculty |
| --- | --- | --- | --- |
| Weekly full sign-off | Weekly | Weekly | Weekly |
| Supervisor-led | Optional | Weekly | Monthly or final |
| Monthly summary | Monthly | Monthly | Monthly |
| Evaluation-only faculty | As needed | Midterm/final | Midterm/final |

Confirm the exact model rather than copying a default from another program.

## Build and test

1. Configure the track and level requirements.
2. Select the cohort's hours report template.
3. Create the report template with the required signers.
4. Assign it to a controlled cohort.
5. Create the recurring schedule.
6. Check the first generated assignment.
7. Use populated demo data to review the completed report and PDF.
8. Confirm the Overview calculations and standard reports use the intended categories.

See [6. Building Forms](/fieldx/building-forms), [7. Creating & Assigning Forms & Reports](/fieldx/step-4-create-assign-tasks), and [8. Setting Up Recurring Tasks](/fieldx/setting-up-recurring-tasks).

## Final checklist

- [ ] Requirements confirmed for every track and level
- [ ] Supervision checked independently
- [ ] Activity types approved
- [ ] Ethics code approved
- [ ] Report template selected before students log hours
- [ ] Signer roles and cadence confirmed
- [ ] Schedule end date configured
- [ ] Completed report and PDF reviewed
- [ ] Known rules the platform cannot enforce are documented
