Assignments live inside a class. Open **Courses** → **My Courses**, click a class, then use the **Assignments** tab.

Need to create the class, invite students, or change class defaults first? See [My Courses](/simulations/my-courses).

<Tip>
  If the class is connected to Canvas, students often launch and get graded from Canvas. The assignment is still built here. See [Canvas LTI integration](/simulations/canvas-lti-integration).
</Tip>

## Pick an assignment type

Click **Create assignment** and choose:

| Type | What students do |
| --- | --- |
| **Case** | Live session with an AI client (walkthrough below) |
| **Quiz** | Multiple choice, true/false, and written questions |
| **Document** | Read a file or URL, and optionally upload their own file |
| **Form** | Complete a form you already created. See [Forms](/simulations/forms) |
| **Peer review** | Review a classmate's case. See [Peer review assignments](/simulations/peer-review-assignments) |

## Case assignments

The case builder has these steps:

<Steps>
  <Step title="Avatar">
    Browse and select the AI client. This includes built-in SimCare cases, faculty-created cases from your school, and any [custom clients](/simulations/client-builder) you've built. Use **Find clients with AI** to describe what you want to practice and let the AI suggest matching clients.
  </Step>
  <Step title="Details">
    Set the assignment title and any instructions students should see. Add **Learning Outcomes** — these power the competency reporting in your Analytics tab.
  </Step>
  <Step title="Settings">
    Configure the assignment behavior:

    | Setting | What it does |
    | --- | --- |
    | **Publish Immediately** | Make the assignment visible to students now (or keep as draft) |
    | **Require Camera** | Students must turn on their camera during the session |
    | **Make Feedback Visible to Students** | Release AI feedback automatically (or hold for instructor review) |
    | **Limit Assignment Attempts** | Cap how many times students can retry |
    | **Allow Students to Archive Attempts** | Lets students hide attempts they don't want graded |
    | **Set Time Limit** | Enforce a maximum session duration |
    | **Require Student Upload** | Students must upload a file with the submission (with size and type limits) |
  </Step>
  <Step title="Assessments">
    Pick written tasks students complete after the session, before they can see feedback:

    - **Problem Statement**
    - **Differential Diagnosis**
    - **Safety Planning**
    - **Risk Assessment**
    - **Treatment Planning**
    - **SOAP Note**
    - **Reflection**
  </Step>
  <Step title="Evaluation">
    Choose how the AI scores student performance. Pick one of the modes below — they're mutually exclusive.

    **General Counseling Skills Assessment (default)**

    Leave the **General Counseling Skills Assessment** toggle on to use SimCare's default case-specific feedback. The AI evaluates the session against the standard counseling competencies tied to the client you picked.

    **Microskills**

    Turn the toggle off to scope feedback to specific microskills. You'll see SimCare's skill taxonomy organized as **Tier → Skill → Microskill**. Enable the skills you want assessed and, if you only care about a subset, toggle individual microskills underneath. Use this when an assignment targets a specific competency (for example, reflective listening or open-ended questions) and you want feedback to ignore the rest.

    <Note>
    Some cases and focused scenarios carry a default microskill rubric. When you select one of these while creating an assignment, the microskills picker pre-fills with that default. You can adjust the pre-filled skills, or select a saved evaluation template to override the default entirely. The pre-fill only happens when you haven't already chosen a rubric, and editing an existing assignment never changes its saved rubric.
    </Note>

    **Saved evaluation template**

    Select a saved evaluation template to score students against your own **rubrics** and **checklists**:

    - **Rubrics** — criteria scored on a column scale (for example, _Excellent / Good / Needs Work_). Each cell carries display text for students and hidden evaluation instructions for the AI.
    - **Checklists** — pass/fail items each worth a fixed point value.
    - **Theory analysis** — enabled per template; when on, the AI also analyzes the session through the theory tied to the template.

    Click **Preview** next to the selected template to open the student-facing view in a new tab.

    Templates can be marked **public** (available to every program) or scoped to specific programs via program access. Only templates your program has access to appear in the picker.

    Selecting a saved template hides the microskills picker and replaces the default per-case feedback in the next step.
  </Step>
  <Step title="Feedback">
    Choose which feedback components appear on student Case Reviews:

    - **Annotated Transcript**
    - **Basic Skills** (Evaluation Checklist)
    - **Theory Analysis** _(auto-selected if you chose a theory)_
    - **Checklist**
    - **Advanced Skills**

    Pick a **therapy theory** for Theory Analysis — over 30 are supported across Beginner, Intermediate, and Difficult tiers (Motivational Interviewing, CBT, Narrative, Gestalt, Adlerian, Bowen Family Systems, Strategic, Structural, Solution-Focused, DBT, Psychoanalytic, and more).

    When a saved evaluation template is selected in the previous step, this step is reduced to the theory picker — the template controls the rubric and checklist sections automatically.
  </Step>
</Steps>

## Quiz assignments

Builder steps: **Details** → **Settings** → **Questions**.

On **Questions**, add:

- **Multiple choice** and **True/False** — auto-graded
- Short written answers (up to 200 characters) or longer written answers (up to 1,000) — you grade these

Set a due date and attempt limit on **Settings**, then create the assignment and **Publish** it when students should see it.

## Document assignments

Builder steps: **Details** → **Settings** → **Content**.

- On **Content**, add the reading (file or URL) students should see.
- On **Settings**, optionally turn on **Require Student Upload** so they must submit their own file (with instructions and type/size limits).

Document assignments do not use attempt limits — students can re-upload if you required a file.

## Trying an assignment

After you create an assignment, open it from the **Assignments** tab and click the **⋯** menu, then **Try assignment**. You can run the case, quiz, or document yourself without affecting student data. A purple **Teacher Preview Mode** banner appears throughout the session.

## Follow-up / longitudinal cases

Follow-ups let students return to the same client across multiple sessions. Each follow-up is tied to a **parent assignment** (the earlier session) and a **scenario** (the clinical situation the client is in when they come back).

### Turning on follow-up mode

In the case assignment builder's **Avatar** step, toggle **This is a follow-up** after selecting a case. Two new fields appear:

- **Parent assignment** — the previous assignment in this class that students must complete first.
- **Follow-up scenario** — the storyline for this session.

The assignment is automatically labeled **Follow Up #N** in the class assignment table for both teachers and students, so the order is clear at a glance.

### Picking a scenario

Each case template ships with a set of numbered scenarios (1, 2, 3…) plus any custom scenarios your school has built (shown as C1, C2…). The picker shows a short summary and a one-line clinical goal for each.

- Scenarios already used by another follow-up in the same class show a **Used** badge so you don't accidentally duplicate them.
- Scenario 6 is reserved as a termination session — selecting it auto-sets the session type to **Termination**.
- The session type defaults to **Intervention** on follow-ups (since intake has already happened).

### Creating a custom scenario

If none of the built-in scenarios fit, select **Not a fit? Create your own** under the scenario picker. The **Follow-up builder** opens in a new tab.

<Steps>
  <Step title="Describe the situation">
    Write 20–3,000 characters describing what has changed for the client since the previous session — life events, symptom changes, relationship updates, anything the AI client should be aware of.
  </Step>
  <Step title="Generate">
    Select **Generate scenario**. SimCare uses AI to structure your free-text into the three fields a scenario needs:

    - A 3–5 word summary
    - A one-sentence clinical goal
    - A 100–120 word vignette that primes the AI client

    Your draft is saved to your school library so any teacher creating a follow-up on the same case can reuse it.
  </Step>
  <Step title="Return to the assignment">
    Close the tab to return to the assignment builder. Your new scenario appears in the picker tagged **C1**, **C2**, and so on.
  </Step>
</Steps>

Each case template can hold up to 10 custom scenarios. Delete ones you no longer need from the Follow-up builder.

## Organizing assignments into modules

Modules let you group a class's assignments into a structured plan students can follow — for example, *Week 1*, *Week 2*, or units by topic. Modules belong to one class. Changing them never affects other classes or course templates.

### Manage modules

On the **Assignments** tab, click **Manage Modules**:

- **Add module** — give it a title and an optional description.
- **Rename** — click the pencil icon to edit the title or description.
- **Reorder** — drag modules by the handle. The order you set is the order students see.
- **Delete** — deleting a module does not delete its assignments. They move to **Other Assignments** at the bottom of the module view.

### Add an assignment to a module

Two ways:

- In the assignment builder's **Details** step (Case, Quiz, and Document assignments), pick a module from the **Module** dropdown. Use **Create new module** inside the dropdown to add one without leaving the form. Modules are always optional — leave it as **No module** if you don't use them.
- On an existing assignment row, open the **⋯** menu and pick a module to move the assignment into it, or **Remove from module**.

Assignments you add to a module are placed at the end of that module.

### View by module

Use the sort dropdown on the Assignments tab to switch between **By due date** and **By module**. The module view groups assignments under collapsible module headers, with unassigned assignments under **Other Assignments**.

Once a class has modules, students get the same **By module** option on their class page.

<Note>
  Duplicating a class copies its modules along with the assignments. Classes created from a course template also keep the template's modules, and you can rename, reorder, or delete them in the live class without touching the template.
</Note>

## Publish, edit, and delete

On the assignment row:

| Action | What it does |
| --- | --- |
| **Publish** / **Unpublish** | Published assignments are visible to students (they get a notification). Unpublished drafts are hidden so you can revise |
| **Edit** | Opens the same builder. Changes to a published assignment apply immediately |
| **Delete** | Removes the assignment for students. If it has follow-up sessions, those follow-ups are deleted too and their submissions are hidden |
| **⋯** | **Try assignment**, **Copy assignment**, **Copy LTI link**, or move the assignment to a [module](#organizing-assignments-into-modules) |

Use **View Submissions** on the row to open the student list for that assignment.

### Editing form assignments

Form assignments support the same edits as other types, with two specifics:

- **Due date changes sync to students.** When you change the due date, every student's pending form task updates to match. Forms a student has already submitted keep their original date.
- **You can swap the attached form only before anyone starts.** Editing the assignment lets you pick a different form, but once any student has started filling it out, the swap is blocked to protect their work. Create a new assignment instead to assign a different form.

## Viewing submissions

Each student row on the Assignments tab shows a status badge:

| Badge | Meaning |
| --- | --- |
| **Not Started** | Student hasn't opened the assignment |
| **In Progress** | Session started but not submitted |
| **Submitted** | Completed and awaiting review |
| **Graded** | Instructor has reviewed and saved a grade |
| **Feedback Released** | AI \+ instructor feedback is visible to the student |
| **Past Due** | Due date passed without submission |

Click a student row (or **View Submissions**) to open their work.

## Grading

### Case submissions

Click **Grade Case** on a submitted row. You'll see the recording, AI feedback, and a grading panel:

1. Optionally add **instructor comments** on the annotated transcript.
2. Enter a **numeric grade** (0–100) and written feedback.
3. Click **Save** to keep a draft the student cannot see yet.
4. Click **Publish Grade** when they should see it.

If the student has more than one attempt, use the **attempt switcher** at the top of the grading view.

**Re-grade** runs a fresh AI analysis of that submission. Give it up to a minute; if it's still stuck, email [hello@simcare.ai](mailto:hello@simcare.ai).

**Unpublish Grade** hides the grade again so you can revise.

**Reset Submission** (on the student row) lets the student start over.

### Quizzes

Open the student's quiz. Auto-graded items are filled in; override scores or add feedback on written answers, then **Publish Grade**.

For the whole class, open **View Submissions** and use **Grade All Quizzes** (or **Grade All Cases** for simulations).

### Releasing feedback

If you held AI feedback for instructor review:

- Per student: **Release Feedback** (or **Unrelease**) on their row
- Whole class: **Release All Feedback** at the bottom of **View Submissions**

High-volume grading also lives at `/grading/bulk-case` and `/grading/bulk-quiz`.

## Class analytics

The **Analytics** tab on your class shows:

- Completion rates by assignment
- Grade distribution
- Per-student progress view
- Competency performance (if learning outcomes are tagged)

Use the period filter to focus on a specific date range. Export the full dataset as CSV or generate a PDF report for individual students or the whole class.

## Troubleshooting

| Problem | What to try |
| --- | --- |
| Students can't enroll | Share the 8-character **Join Code** from **Members → Invite → Add Student**. Same code is on the course-card **⋯** menu |
| Assignment not visible | Confirm it is **Published**. Drafts are hidden from students |
| Student used all attempts | **Edit** the assignment and raise the attempt limit |
| Grade not showing in Canvas | Confirm the assignment is linked as an External Tool, then publish the grade again. See [Canvas LTI integration](/simulations/canvas-lti-integration) |
| Quiz auto-grade looks wrong | Override the score in the grading view and **Publish Grade** |
| Re-grade didn't update | Wait about a minute, then refresh. If it stays stuck, email [hello@simcare.ai](mailto:hello@simcare.ai) |

Need more help? Email [hello@simcare.ai](mailto:hello@simcare.ai).
